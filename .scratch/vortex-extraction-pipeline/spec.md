# 规格书：迹线 Transformer 涡提取管线（vortex-extraction-pipeline）

**Status:** ready-for-agent

> 事实来源：`HANDOFF.md`（唯一权威；决策 §1、已核实事实 §2、参数 §6、风险 §7）。本规格是 HANDOFF 的工程化投影，冲突时以 HANDOFF 为准并在其 §11 记录修正。

## Problem Statement

作为流场分析者，我在 2D 非定常仿真流场（当前数据集：ETH "2D Unsteady Cylinder Flow Around Corners" 的 `pipedcylinder2d.nc`，450×150×1501）上做涡提取。传统判据（IVD/Q-criterion）是逐帧网格方法，而 VortexTransformer 论文（CGF 2025，DOI 10.1111/cgf.70042）的**迹线 Transformer**（`PathlineTransformerV0`）直接从迹线（pathline）输出每条迹线的涡概率，再投影回网格——这是一种以流线几何为输入的深度学习方法。

问题是：参考仓库（PyflowVis-main，只读参考）不是可运行于本项目环境的工程（依赖 numba/pybind/GUI/wandb、C++ 迹线生成器不支持离散场、配置系统依赖 multimethod），数据与标签也没有现成管线。我需要一个**自包含、可复现**的工程：从原始 nc 场出发，完成掩膜、迹线提取、弱标签、数据集、训练（VS Code Remote-SSH 服务器 GPU）、推理评估全链路，最终输出可信的涡提取结果（对比图、动画、弱定量表、多阈值敏感性报告）。

## Solution

从零构建一个自包含的涡提取管线（代码迁移自参考仓库的最小纯 torch 子集，保留 Apache 2.0 署名），在多数据集上从头训练迹线 Transformer（联合线 130 epoch，服务器单卡默认，逐 epoch checkpoint + `--resume auto`），用 TTA 推理把逐迹线涡概率投影回网格，交付与 IVD/Q-criterion 参考并排的定性对比与弱定量评估。

管线分为四个构建单元（垂直切片素材）：

1. **数据准备单元**：固体几何掩膜（逐数据集预处理）→ 全局场迹线提取（256 条/样本，7 通道）→ 弱标签（IVD 阈值 + 连通域过滤）→ 数据集类（时间划分、patch 窗口采样、memmap 预计算、正样本过采样）。
2. **模型单元**：vendor 迁移（模型/损失/工具的最小纯 torch 子集，剔除拖入 numba 等的模块）→ 从零训练脚本（TwoStep 调度、断点续训、可选 DataParallel/AMP）。
3. **评估单元**：TTA 滑窗推理 → 网格投影 → 对比图/动画/弱定量表 → 多阈值敏感性报告。
4. **交付单元**：结果归档、复现 README、参数表。

## User Stories

1. 作为流场分析者，我想对任意 2D 非定常仿真场得到逐迹线涡概率并投影成网格图，以便以深度学习方式定位涡结构。
2. 作为流场分析者，我想让预测涡区域与 IVD/Q-criterion 参考结构一致（涡街、拐角回流区）且无明显碎裂噪声，以便相信模型学到的涡概念。
3. 作为开发者，我想在本地 CPU 快速验证掩膜/迹线/标签的正确性（冒烟目检），以便在花 GPU 预算前发现几何与数值问题。
4. 作为训练者，我想通过 VS Code Remote-SSH 在服务器训练（每 epoch 存 checkpoint、SSH 会话中断后可无损续训），以便使用稳定的 GPU 环境。
5. 作为训练者，我想用与论文一致的口径训练（256 条迹线/样本、7 通道、BCE、TwoStep 调度、batch 100、200 epoch），以便对齐论文可复现性。
6. 作为评估者，我想拿到多个代表性时间步的"模型输出 vs IVD vs Q-criterion"并排对比图与 mp4 动画，以便定性判断涡提取质量。
7. 作为评估者，我想拿到弱定量表（对 IVD 阈值的 F1/IoU、涡面积占比、帧间连续性），以便量化评估而非只靠眼观。
8. 作为研究者，我想拿到多阈值敏感性报告（弱标签阈值 τ 的稳健性），以便理解评估对标签口径的依赖。
9. 作为使用者，我想对新数据集用一条命令生成固体掩膜并接入训练（掩膜逐数据集预处理，不进入模型输入），以便扩展更多仿真数据集。
10. 作为开发者，我想在本地 CPU 跑通一次完整前向与 1~2 步训练（无 CUDA），以便快速迭代调试。
11. 作为数据工程师，我想 train/val/test 严格按时间划分（10s/12.5s/15s，无时间泄漏），以便评估可信。
12. 作为使用者，我想数据集路径含中文也能直读（h5py），以便在本机直接使用现有数据目录。
13. 作为评估者，我想推理结果确定可复现（TTA 平均或确定性采样开关），以便对比与报告不因随机 PSL 采样抖动。
14. 作为训练者，我想 checkpoint 归档且含 optimizer 状态，以便跨 SSH 会话无缝续训。
15. 作为使用者，我想迹线在固体区域被正确处理（种子重播种、迹线截断重复末点、不引入毒值），以便几何不影响特征质量。
16. 作为开发者，我想迁移代码自包含、不 import 参考仓库（且保留 Apache 2.0 署名文件），以便工程可独立演进。
17. 作为研究者，我想理解 KNN 时空混合度量（t_scale）对结果的影响（冒烟对比 0.1/0.25/1），以便确认尺度选择。
18. 作为使用者，我想正负样本平衡（50% 正样本过采样），以便 BCE 训练不被类别失衡主导。
19. 作为开发者，我想训练脚本不依赖原仓库 train.py 的任何行为（自写），以便可控、可审计。
20. 作为复现者，我想按 README 从零复现全流程（数据→训练→评估），以便结果可验证。

## Implementation Decisions

- **工程形态**：自包含工程；从参考仓库复制最小纯 torch 子集进 vendor 目录（模型、损失、工具），重写工具包的 `__init__.py` 剔除依赖 multimethod 的配置模块；**不**迁移数据集、流场工具、训练/测试脚本、Misc 模块（拖入 numba/pybind/GUI/wandb）；保留 LICENSE/NOTICE 署名。判据：本地 `build_model_from_cfg` 可导入；此后全项目不引用参考仓库。
- **数据读取**：一律 h5py（实测 netCDF4 C 库打不开中文路径；h5py 可直接读）。字段：tdim/xdim/ydim/u/v + Re、nu、radius 元数据。
- **固体掩膜**：|v|<ε 逐帧取与 → 连通域标记 → 输出掩膜（种子排除、迹线截断、IVD 置零共用）；圆柱 = 不与壁相连的孤立连通块；无障碍物数据集输出空掩膜、代码路径不变。掩膜随数据集 (T,Y,X) 存储，逐数据集预处理，不进入模型输入。
- **迹线提取**：全局场积分（允许离开 patch），RK4 每输出步 4 子步 + 三线性时空插值；每样本 256 条 = 64 组 × 4 轴向卫星点（不含中心），Δ = patch 边长×0.05，组主序编组；种子落固体 → 重播种（仿 C++ JittorReSeeding）；迹线入固体 → 截断并重复末点（不引入 -1000 毒值）；位置按 patch 归一化到 [-1,1]（可超界）。
- **弱标签**：中心差分 ω=∂v/∂x−∂u/∂y；IVD=|ω−5×5 局部邻域均值|；标签 = 种子点处 IVD ≥ τ（τ 默认 95 分位数、逐时间片）+ 5×5 最小面积连通域过滤；固体区 IVD=0。直接弱标注，**不走** Vatistas 参数拟合/合成数据管线。
- **样本通道**：C=7 = [px, py, t, ivd, distance(距种子点), u, v]；归一化：px,py → patch 内 [-1,1]；t → [0,1]×t_scale（默认 0.25，KNN 时空混合度量权重，冒烟对比 0.1/0.25/1）；ivd 标准化；distance 用归一化坐标；u,v ÷ 全局最大速度。
- **数据集划分与采样**：train [0,10]s / val (10,12.5] / test (12.5,15]（帧 0-1000 / 1000-1250 / 1250-1500）；patch 32×32 stride 16、窗口 T_win=24 帧、窗口起点步长 4 帧；每 epoch 40000 样本（下限 20000）、50% 正样本过采样（正样本 = patch 内存在 ≥1 条涡迹线）；u,v 与预计算 IVD 存 memmap（IVD 一次算好 ≈405MB）；返回 `((dummy_field, pathlines), labels)` 匹配模型输入。
- **模型**：`PathlineTransformerV0` 从头训练，不使用预训练权重与仓库 demo 验证集。PSL：组置换 + 空间下采样（64→32 组）+ 时间下采样（16→8）→ 1024 点；3 层 KNN Point-Transformer（k=16，相对位置编码）；全局池化 mean+max；特征传播回全部 256 条；sigmoid 每迹线涡概率；损失 BCE。
- **训练**：AdamW(wd 1e-6)、lr 1e-4、TwoStep（warmup 60 epoch → 5e-6）、batch 100、联合线 130 epoch、梯度裁剪 1.0；每 epoch 存 checkpoint（含 optimizer 状态）；服务器按实测选择单卡/DataParallel，AMP 默认关闭；`--resume auto` 跨 SSH 会话恢复，不依赖会话时限或分块。
- **推理评估**：滑窗推理（patch stride 16 覆盖全场）→ TTA 5 次平均（PSL 随机采样）→ 网格投影（累积+计数平均消除 patch 重叠）→ 展示帧用加密种子（每 2×2 输出像素一组十字）→ 底图用速度模场（不依赖 LIC 渲染器）→ 对比图 + mp4 动画 + 弱定量表（F1/IoU、涡面积占比、帧间连续性）+ 多阈值敏感性报告。
- **配置**：训练/数据超参集中于 YAML 配置，与代码分离。
- **验收对齐**：HANDOFF §3 四条验收标准（结构一致、130 epoch 联合线归档可续训、对比图+动画+弱定量表+README、多阈值报告）。

## Testing Decisions

- **好测试的定义**：只测外部行为、不测实现细节；期望值来自独立来源（已知字面量、论文口径、规格参数），不重算实现路径；属性测试（计数、有限性、连通性）用于数据管线。测试名与断言使用 HANDOFF 领域词汇。
- **接缝（与用户确认，三条全用，端到端为主验收缝）**：
  1. **数据准备缝**：原始 nc 场 + patch/窗口参数 → (7 通道迹线张量, 弱标签)。测试：冒烟目检（掩膜/迹线/标签图）+ 属性测试（掩膜连通性、迹线计数恒 256、特征有限无 NaN、固体区 IVD=0、时间划分无泄漏）。
  2. **模型缝**：迹线样本 → 每迹线涡概率。测试：前向输出形状 (B, 256)、数值域 (0,1)；训练 loss 下降（CPU 冒烟 1~2 步 + 服务器全量 test F1 记录）。
  3. **端到端缝（主）**：nc 文件 + 时间窗 → 网格化涡概率场（可画图/可量化）。测试：展示帧对比图目检（涡街/拐角回流区结构一致、无明显碎裂噪声）+ 弱定量表（F1/IoU、涡面积占比、帧间连续性）+ 多阈值敏感性表。
- **被测模块**：数据准备单元（掩膜、迹线、标签、数据集划分/采样）、模型单元（前向、训练循环、checkpoint 续训）、评估单元（TTA、投影、定量指标）。
- **测试环境**：本地 CPU 跑冒烟与属性测试（3~5 个 patch×24 帧窗口）；全量训练/评估在 VS Code Remote-SSH 服务器（已核实 PyTorch 2.7.1+cu118、4×RTX 3090）。
- **先例**：绿地项目无既有测试；超参与判据先例 = 论文附录 C 与 HANDOFF §2/§6 已核实事实。

## Out of Scope

- Vatistas 参数拟合与合成数据管线（决策 1 明确不走）。
- 使用参考仓库预训练权重与 demo 验证集（决策 2；模型可用性已在既有实验中确认，不在本项目范围）。
- ivd 遮除消融（决策 5：IVD 是公认高精度涡判据，模型学习其近似是可接受且预期的）。
- 多数据集联合训练（**已入范围**：票 07 延伸——6 个新数据集 + pipedcylinder2d 共 7 个，各数据集帧前 60% 训/后 40% 测的 frac 划分、τ 与归一化逐数据集各自；掩膜逐数据集预处理，不进模型输入。规格主体原 Out of Scope 条目作废，以 HANDOFF §11 票 07 延伸记录为准）。
- LIC/高级渲染（底图用速度模场即可）。
- GUI 与交互式可视化。
- 多机/分布式训练（DataParallel 仅在服务器明确预留多卡时启用，AMP 默认关闭）。
- 3D 流场与三维迹线。

## Further Notes

- 本规格不取代 HANDOFF：HANDOFF §1 决策、§2 事实、§6 默认参数表、§7 风险预案在规格之上持续权威；工程事实变化时按 §11 协议更新 HANDOFF。
- 服务器共享 GPU 与 SSH 会话中断 → 每 epoch checkpoint、`--resume auto`，运行前用 `nvidia-smi` 选择空闲卡；缓存和临时文件统一放 `/data/xuziyi/`。
- 风险预案（§7）在实现票中逐条落实：阈值敏感性报告、配额/时长、正负平衡、涡特征微弱（τ 下探 / T_win 24→48）、迹线撞固体、KNN 时空尺度（t_scale 对比）、推理非确定（TTA/确定性开关）、中文路径。
- 未决待冒烟定值：τ 具体值、t_scale 取值、epoch 样本数（HANDOFF §6 已给默认，阶段 1/2 校准后回写）。
